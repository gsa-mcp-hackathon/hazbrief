## The TEVV reading

The data the brief gathers is a set of DN-010 records. Verification and validation each have their own instrument:
- **Verification:** a record is verified by being used. It is drawn as a layer or printed as a line, and a test asserts the drawn or printed thing. That is this table's `Verified by` column.
- **Validation:** the brief is validated by a review that reads it on the reference scenario. That is the `validated by:` record in a row's Status cell (a `Validated by` column until HB-149).

The display is the test surface for both. DN-019 section 1 makes checking the one cognitive act the first screen is built around: does the picture agree with what the reader sees out the window. The operator's review of 2026-11-07 failed that check on the brief's own two layers (Issue `90ac45af`: the arrow pointed east, the plume ran SSW). HB-133 ADDENDUM-01 section 4 fixes where validation happens. It runs on one reference scenario, the chlorine rail brief (`csx-point-of-rocks-day` and `-night`), until the page is right. One renderer draws every brief, so a defect seen there is seen everywhere.

## The review cycle rule

A review finding becomes a row change in the task that fixes it:
- that task sets the row's status to `changed` and cites the finding, with its date, as a `validated by:` record in the row's note (`seldon req update VR-NNN --note "changed; validated by: <finding> (<date>)"`);
- a later review on the reference scenario moves the row back to `satisfied` or to `open`.

HB-130R, HB-131R and HB-132R each add a line to their RESULT naming the `VR` rows they satisfied. A task that adds a display test either cites the row the test verifies or adds a row. A test with no row is an orphan, listed in the export.

## Columns and states

- **Requirement:** one sentence, testable. No adjective without a number or a named convention.
- **Set by:** the governing text, a key from the table below plus a section, e.g. "DN-019 §3 row 2". Rows are derived from these texts, never invented here. A surface the texts name without a testable sentence reads "not yet specified" and cites the section.
- **Verified by:** test nodes (`tests/<file>::<node>`, parameters dropped), or "none yet". "none yet" is counted, and the count may only fall.
- **Status:** the state's label, then the row's note. Since HB-149 (seldon SEL-035, AD-013-R4) the cell is computed: a row is changed with `seldon req update`, never here. The note carries the `validated by:` record, the review finding or operator answer that confirmed or changed the row, with its date (until HB-149 its own `Validated by` column, which no graph edge computes). A row no review has read has none.
  - `satisfied`: the code does it. This is the RTM's "met". Where Verified by reads "none yet", the code was read and no test checks it.
  - `open`: the code does not do it, or does part of it. This is the RTM's "partial" or "not met", and the row says what is missing.
  - `changed`: a review finding changed the requirement, and the fix is verified by its test. The row awaits the next review on the reference scenario.
  - `withdrawn`: a later governing text removed the requirement. The row is kept, with what replaced it.
  - `implemented` (HB-149): the row was called `satisfied` or `changed`, but no test verifies it; it reads `implemented: satisfied` or `implemented: changed` until a test carries `@pytest.mark.verifies("VR-NNN")` and `seldon req trace` and `seldon req update VR-NNN --state verified` run. Verified by reads "none yet".
